# Публикация physogezic на GitHub

Подготовленный каталог репозитория: `Z:\YandexDisk\ПетПроекты\Физогэзик\physogezic`.
Remote: `https://github.com/Altersam/physogezic`.

Для переноса целиком создаётся `physogezic-source.zip`: в нём исходники, `.github`, Godot-проект, документация и графика. `.git`, сохранённые комнаты, журналы и кэши не упаковываются. Повторная упаковка: `python tools/package_repository.py` из подготовленного репозитория.

## Веб-игра через GitHub Pages

1. Загрузите изменения из подготовленного каталога в ветку `main` репозитория.
2. На GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Запустите workflow **Publish web game** во вкладке Actions либо дождитесь его запуска после push.
4. После успешного развёртывания адрес игры: **https://altersam.github.io/physogezic/**.

Workflow проверяет правила, собирает `dist/site` по явному списку ресурсов и публикует его. Технические журналы, состояния комнат, оригинальные документы и файлы сервера в сайт не попадают.

На Pages доступны настолка за одним экраном, приключение, формулы и локальный прогресс. GitHub Pages отдаёт статические файлы; процесс Node.js для комнат там не запускается. На статическом сайте интерфейс показывает, как открыть сетевой вариант.

## Комнаты с телефонов прямо из GitHub Codespaces

1. В репозитории выберите **Code → Codespaces → Create codespace on main**.
2. После подготовки окружения выполните в его терминале `npm start`.
3. Откройте проброшенный порт **4173**. Для подключения других участников выставьте этому порту видимость **Public** во вкладке Ports.
4. Создайте стол во вкладке «С друзьями». Код автоматически использует внешний адрес Codespaces в QR-приглашении.

Конфигурация `.devcontainer/devcontainer.json` уже задаёт Node.js и проброс нужного порта. Никакие npm-пакеты устанавливать не требуется.

Другие варианты сетевого запуска — `Сетевая игра.cmd` на компьютере ведущего или контейнер:

```sh
docker build -t physogezic .
docker run --rm -p 4173:4173 -v physogezic-data:/data physogezic
```

Для опубликованного адреса можно передать `PUBLIC_BASE_URL=https://адрес-игры`. Состояние комнат хранится в `/data` контейнера.

## Godot

Откройте **`Godot3D/project.godot`** в Godot 4.5+ и нажмите F5. Это локальная 3D-игра за одним компьютером с теми же 45 вопросами, собственной анимацией и звуками.

Workflow **Verify web and Godot** устанавливает Godot 4.5.1, прогоняет партию и сценарий эффектов. В его артефактах появляется исходный проект `physogezic-godot-project`, который можно скачать и открыть в редакторе. Это исходный проект, не экспортированный `.exe`.

## Проверки на своём компьютере

```sh
npm test
python tools/build_site.py
python tools/check_table.py
python tools/check_godot.py --godot путь-к-Godot
```

Для `check_table.py` нужны Playwright и Chromium. Для Godot-проверки нужен редактор Godot 4.5+. Параметр `--screenshots` дополнительно проверяет настоящую отрисовку и звуки на draw/card/correct/wrong/victory-сценариях.

## Почасовая очистка

- Серверный `data/logs/runtime.log` обнуляется в начале нового часа; записи нового часа идут в тот же файл.
- Godot ведёт `user://logs/game.log` с такой же почасовой очисткой.
- Панели «Последние ходы» показывают только текущий час и очищаются автоматически.
- Сохранение поля, очереди, ответов и итоговых результатов находится отдельно от технического журнала и продолжает работать.

`.gitignore` исключает журналы, локальные комнаты, кэш Godot, исполняемые файлы редактора и собранные архивы. Существующая `.git`-папка репозитория сохранена; подготовка файлов сама по себе не создаёт commit и не выполняет push.
